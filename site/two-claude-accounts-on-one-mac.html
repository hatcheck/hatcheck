Two Claude accounts on one Mac

Claude Desktop keeps one login. To be signed in to a work account and a personal one at the same time, it has to run twice, each run with its own data folder. This page shows the folder trick itself, which is one command, and what hatcheck adds on top: a launcher per account in /Applications, with Claude's icon in a colour of its own, that opens that account's Claude or brings it forward. No login is read, copied or shared: each Claude signs in on its own, as it always did.

What a second data folder does

Claude Desktop is an Electron app. Started with --user-data-dir, it keeps everything in that folder instead of its usual one: the login, settings, sessions, MCP servers and Cowork data. So one command opens a second Claude that knows nothing of the first:

open -n -a /Applications/Claude.app --args --user-data-dir="$HOME/.claude-instances/work"

That idea is Philipp Stracker's, and it works on its own. Two things make it unpleasant to live with:

  • Every run of that command starts another process, even when one is already open on that folder. Only the first process on a folder gets its login; a second one on the same folder comes up signed out, and two on one folder can damage it.
  • Nothing tells the two Claudes apart in the Dock or Launchpad: the same icon, the same name.

What hatcheck adds

hatcheck desktop new makes a small launcher app in /Applications for each account, named as you like, with Claude's icon recoloured. A click opens that account's Claude if it isn't running, and brings it forward if it is, so there's never a second process on one folder. The Claude it starts is the one Claude.app you already have, with that account's folder, so Claude updates itself as it always did.

Set it up

  1. Install the CLI, with one line in Terminal or with Homebrew. It installs no agent and changes nothing about your Claude: 
    curl -LsSf https://github.com/hatcheck/hatcheck/releases/latest/download/hatcheck-installer.sh | sh
brew install hatcheck/tap/hatcheck    # or, with Homebrew
  2. Make a launcher per account. The first word names the data folder, the quoted one is what the app is called, and --hue turns the icon's colours by that many degrees, with about 110 green, 190 blue and 240 purple: 
    hatcheck desktop new work "Work" --hue 190    # Claude Work.app, blue, with ~/.claude-instances/work
hatcheck desktop new home "Home" --hue -10    # Claude Home.app, red-orange
  3. Open each from Launchpad, Spotlight or the Dock, and sign in to its account the first time. The first time a launcher brings a window forward, macOS asks whether it may control System Events: allow it, once per launcher.

That's it. The Dock shows two Claudes in two colours, each signed in to its own account, and a click on either goes to that one.

Make one for the account you use most, too

Claude Desktop has no lock per data folder, and only the first process on a folder gets its login. So the setup that holds up is an instance per account, the one you use most included, and leaving the stock Claude icon alone day to day: a launcher pointed at Claude's built-in folder while the stock icon also runs it would be a second, signed-out window. Starting fresh means signing in once. To carry over the login, settings, MCP servers and sessions you already have instead, copy Claude's built-in folder into the instance while Claude is fully quit, as docs/desktop-instances.md shows.

⌘W closes a window and leaves that Claude running, so the next click brings it straight back; ⌘Q quits it.

Everyday commands

hatcheck desktop                # the instances, and which are running
hatcheck desktop open work      # the same as clicking the launcher
hatcheck desktop remove home    # delete the launcher; --data deletes its data folder too, login and all

What stays yours

  • The data folders are Claude's own, in ~/.claude-instances, and each Claude signs in itself. Hatcheck never asks for, reads, copies or moves a login.
  • Nothing runs in the background: a launcher runs for the moment of a click.
  • Removing hatcheck leaves the instances and their logins as they are. hatcheck desktop remove takes a launcher away, and --data the folder with it.

The rest of what hatcheck never does, each with the code that keeps it: rules it keeps.

Windows and Linux

Claude Desktop is an Electron app there too, so a data folder per account should work the same way; the launchers haven't been built for them yet (roadmap). The command-line side, a Claude Code profile per account included, works on all three.

The app

A menu-bar app is on its way that makes an instance with a button and a colour of your choice, and shows what's left of each plan and the last day's sessions. Until its first release, the three commands above are the way; the app says where it stands.
