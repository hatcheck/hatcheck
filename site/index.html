Hatcheck

Claude Code, Codex, Kimi Code CLI, DeepSeek Harness, MiniMax Code and Qwen Code accounts on one computer, each kept apart, and Antigravity CLI and ZCode beside them: recent sessions, plan usage and resume or open commands, with sessions carried between the original five and Qwen Code, and out of DSH and mcode.

Start with a profile per account

Claude Code keeps its login, settings and sessions in one folder, ~/.claude. Pointed at another folder with CLAUDE_CONFIG_DIR, it keeps a second set there, with a login of its own: a profile. Hatcheck is built on that: a folder per account, and cl to run Claude Code with one. Codex and Kimi Code CLI work the same way, with CODEX_HOME and KIMI_CODE_HOME, and cx and ck run them.

cl a                 # Claude Code with ~/.claude-a; the first run asks you to sign in
cl b                 # ~/.claude-b, signed in to another account
cx a login           # Codex with ~/.codex-a
ck a login           # Kimi Code CLI with ~/.kimi-code-a
cd ~/code/api
hatcheck bind a      # in this repo, plain cl means cl a, and cx and ck the same
hatcheck             # the sessions here from every profile, and what's left of each plan

An existing ~/.claude counts as a profile too (hatcheck calls it default), and plain claude keeps using it. Antigravity CLI and ZCode keep one login each, so hatcheck reads their one folder beside the profiles. DeepSeek Harness homes move with DSH_HOME, MiniMax Code homes with MINIMAX_DATA_DIR and Qwen Code homes with QWEN_HOME, all read-only: which agents, and how far. The CLI comes first: install it, and any agent you don't have yet.

What it does

What to resume, and what's left

hatcheck lists recent sessions from every profile and home, and Antigravity CLI's and ZCode's beside them, with the command that resumes each or opens DSH's session history, and what's left of that plan. hatcheck usage shows every plan, sorted by what's left of Fable; hatcheck best shows the best account now and the move command that carries a session to it.

Sessions that travel

hatcheck move carries a session to another profile when one account runs low, back again later, converts it for any of the eight agents, as a file the agent is started on for those without an importer; --brief hands over a brief in place of the whole conversation. hatcheck fork brings one in as a new session and keeps the original; hatcheck open resumes one in a new terminal or opens DSH's web UI, in its folder, and hat r carries on the newest session from the folder in this terminal, after asking.

Claude Desktop, one per account

On macOS, hatcheck desktop new a A makes a Claude Desktop instance with its own data folder and login, and a launcher in a colour you pick that brings a running instance forward instead of opening a second one.

When a project folder moves

Claude Code files each session under the folder it ran in, and Codex records the folder in each session file, so once a project folder is renamed or moved, resuming from the new place finds nothing. hatcheck relocate brings the folder's sessions along, in every profile and home at once:

$ mv ~/code/web ~/code/site
$ hatcheck relocate ~/code/web ~/code/site
✓ Relocated 4 sessions from ~/code/web to ~/code/site:
  ~/.claude-a  1 session: projects/-Users-me-code-web renamed projects/-Users-me-code-site
  ~/.claude-b  2 sessions: projects/-Users-me-code-web renamed projects/-Users-me-code-site
  ~/.codex  1 session: the folder in the file rewritten
⚠ Left alone: Kimi Code CLI session 8d4b5e6f in ~/.kimi-code is filed under a hash of the folder, which stays as it was.
⚠ Left alone: DeepSeek Harness session d54e0010 in ~/.dsh keeps an immutable folder in its session header and workspace state, which stay as they were.
⚠ Left alone: MiniMax Code session c54e0010 in ~/.minimax keeps shared SQLite state and absolute manifest paths with related assets, which stay as they were.
⚠ Left alone: Qwen Code session 5c5d0e0e in ~/.qwen is filed under the folder's name and records it on every line, which stay as they were.
The folder binding of ~/code/web moved to ~/code/site.
Resume them from ~/code/site. To undo: hatcheck relocate ~/code/site ~/code/web

Only the folder each session records is rewritten; what the conversation says about the old path stays as it was. Antigravity CLI and ZCode keep the folder in their own databases, which hatcheck never writes, Kimi Code CLI files sessions under a hash of it, DSH keeps it in an immutable header and workspace state, mcode keeps shared SQLite state and absolute manifest paths with related assets, and qwen files the transcript under the folder's name and writes the folder on every line, so theirs stay as they are, and it says so. --dry-run shows what would move, a session that's open or still being written stops it before anything changes, and running it the other way round undoes it, byte for byte.

Every command in a few letters

hat is hatcheck's short name, and each command can be cut to its first letters. In a project folder:

hat                 # the sessions here, with resume commands and plan usage
hat u               # what's left of every plan
hat b               # the best account now
hat m               # move the newest session here to it, after asking
hat m 3f1c2a9e b    # or session 3f1c2a9e to ~/.claude-b
hat r               # carry on the newest session here, after asking
ShortForWhat it does
hathatcheckthe recent sessions, with the command that resumes each and what's left of its plan
hat uusagewhat's left of every plan
hat bbestthe best account now, and the command that carries a session to it
hat mmovecarry a session to another profile, or convert it for another agent
hat fforkbring a session into another profile as a new one, keeping the original
hat rresumecarry on the newest session here, in this terminal
hat oopenresume a session in a new terminal, in its folder
hat sshowread a session's conversation
hat wwherefind a session's files
hat relrelocatebring a moved folder's sessions along
hat bibindtie this folder to a profile
hat ununbinduntie it again
hat ddesktopClaude Desktop instances, on macOS
hat pproviderthe keys and models behind claude-z and claude-k
hat dodoctorwhich copies of hatcheck and the agents are installed, and which run

A longer start works too, such as hat mo, and options follow as after the whole name: hat u --cached. Where two commands start with the same letter, the one used more gets it, so bind, unbind and doctor take two letters and relocate three; what hatcheck prints uses the whole name. The launchers are short too: cl a, cx a and ck a run Claude Code, Codex and Kimi Code CLI with profile a (a profile per account).

Install the CLI

macOS, Linux and Windows: one binary per platform, nothing else needed. It installs hatcheck and hat, its short name, with cl, cx, ck, claude-z and claude-k, but no agent: get those from their makers. Installed more than one way, hatcheck doctor says which copy runs and how to remove the rest.

curl -LsSf https://github.com/hatcheck/hatcheck/releases/latest/download/hatcheck-installer.sh | sh
brew install hatcheck/tap/hatcheck  # Homebrew, on macOS and Linux
uv tool install hatcheck            # or: pipx install hatcheck
cargo binstall hatcheck             # the release binaries, with cargo-binstall
cargo install hatcheck              # or build them from crates.io

On Windows, in PowerShell:

powershell -ExecutionPolicy Bypass -c "irm https://github.com/hatcheck/hatcheck/releases/latest/download/hatcheck-installer.ps1 | iex"

Or build it from a clone, with Rust; run ./install.sh again after a git pull:

git clone https://github.com/hatcheck/hatcheck
cd hatcheck && ./install.sh         # Windows, in PowerShell: .\install.ps1

The app

A menu-bar app (system tray on Windows and Linux) built on the CLI: what's left of every plan, the last day's sessions with Resume and Copy, the Claude Desktop instances a click away, and a notification when a limit runs low or resets. Its main window browses every session with a preview, moves or forks sessions between profiles after a dry run, and adds profiles.

It isn't released yet. Its first release brings these downloads and a Homebrew cask, and it updates itself from the releases after that; until then, desktop/README.md says how to build it.
