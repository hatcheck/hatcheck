Hatcheck

Claude Code, Codex and Kimi Code CLI accounts on one computer, each kept apart, and Antigravity CLI and ZCode beside them: recent sessions, plan usage and resume commands across all of them, and sessions carried between all five.

What it does

One profile per account

cl work runs Claude Code with ~/.claude-work, cx work runs Codex with ~/.codex-work, ck work runs Kimi Code CLI with ~/.kimi-code-work: each with its own login, settings and sessions. Bind a folder to a profile, and the name can be left out there.

What to resume, and what's left

hatcheck lists recent sessions from every profile and home, and Antigravity CLI's and ZCode's beside them, with the command that resumes each and what's left of that plan. hatcheck usage shows every plan, sorted by what's left of Fable; hatcheck best shows the best account now and the move command that carries a session to it.

Sessions that travel

hatcheck move carries a session to another profile when one account runs low, back again later, or converts it between Claude Code, Codex, Antigravity CLI, Kimi Code CLI and ZCode. hatcheck fork brings one in as a new session and keeps the original; hatcheck open resumes one in a new terminal, in its folder, and hat r carries on the newest session from the folder in this terminal, after asking.

Claude Desktop, one per account

On macOS, hatcheck desktop new work Work makes a Claude Desktop instance with its own data folder and login, and a launcher in a colour you pick that brings a running instance forward instead of opening a second one.

hatcheck, usage, where, show, desktop, move, fork, relocate and doctor take --json,
for scripts, status bars and the desktop app.

`hatcheck SUBCOMMAND --help` lists a subcommand's options, and hatcheck --version
says which version this is. hat is the short name: hat usage is hatcheck usage,
and so on. cl, cx and ck run Claude Code, Codex and Kimi Code CLI with a profile.

A subcommand can be cut to its first letters: hat m is hat move, hat f is hat
fork. Where two share a letter, it goes to the one used more: b is best, s is
show, u is usage, d is desktop and r is resume, so bind, unbind and doctor take
two letters, bi, un and do, and relocate three, rel.

Install the CLI

macOS, Linux and Windows: one binary per platform, nothing else needed. It installs hatcheck (hat for short, and each command to its first letters: hat m is hat move), cl, cx, ck, claude-z and claude-k. Installed more than one way, hatcheck doctor says which copy runs and how to remove the rest.

curl -LsSf https://github.com/hatcheck/hatcheck/releases/latest/download/hatcheck-installer.sh | sh
brew install hatcheck/tap/hatcheck  # Homebrew, on macOS and Linux
uv tool install hatcheck            # or: pipx install hatcheck

On Windows, in PowerShell:

powershell -ExecutionPolicy Bypass -c "irm https://github.com/hatcheck/hatcheck/releases/latest/download/hatcheck-installer.ps1 | iex"

Or build it from a clone, with Rust; run ./install.sh again after a git pull:

git clone https://github.com/hatcheck/hatcheck
cd hatcheck && ./install.sh         # Windows, in PowerShell: .\install.ps1

The app

A menu-bar app (system tray on Windows and Linux) built on the CLI: what's left of every plan, the last day's sessions with Resume and Copy, the Claude Desktop instances a click away, and a notification when a limit runs low or resets. Its main window browses every session with a preview, moves or forks sessions between profiles after a dry run, and adds profiles.

It isn't released yet. Its first release brings these downloads and a Homebrew cask, and it updates itself from the releases after that; until then, desktop/README.md says how to build it.

Rules it keeps

Not a gateway. Hatcheck is never between an agent and its model. It rewrites no agent's config, holds no login, and runs nothing in the background. Tools such as magpie put a local gateway in that path so any agent can use any model and accounts can take over from each other when a quota runs out. If that is what you want, use one of those. Hatcheck is for the opposite case: keeping a work account and a personal account apart, and knowing which one each session ran on.

Each rule links to the code that keeps it, so it can be checked rather than taken on trust.

  • Not in the path. cl, cx and ck set CLAUDE_CONFIG_DIR, CODEX_HOME or KIMI_CODE_HOME and run the agent in their place; nothing stays running (launch.rs, run).
  • No agent's config is rewritten, except when you ask: hatcheck bind --hook adds one hook to each Claude Code profile's settings, each Codex home's and Antigravity CLI's, or points the one it added at the hatcheck it finds now, and unbind --hook removes only what it added (bind.rs, add_hooks).
  • No credentials. It never asks for, stores, refreshes or moves a login. For Claude it never reads one: Claude Code's own /usage is run in the profile and the snapshot it saves is read. For Codex, the home's token is sent only to ChatGPT's usage endpoint, as it is, never refreshed (usage.rs, run_claude_usage and fetch_codex_usage). For Kimi, the home's token is sent only to Kimi's usage endpoint, as it is, never refreshed. For Antigravity CLI it never reads one either: agy's own /usage is run, once agy models has said it's signed in, since agy asked without a sign-in would start one (agy.rs, run_usage). Signing in happens in the agents themselves, in a terminal.
  • Live usage is opt-in in the app, and --cached in the CLI shows what Claude Code and Codex last saved, and the last readings hatcheck kept of agy's and Kimi's, which save none, with their age.
  • No automatic switching between accounts. hatcheck best ranks and prints commands, for choosing between accounts you may use for the work at hand, such as your own and your company's; nothing starts, moves or switches a session on its own (best.rs).
  • Nothing leaves your computer except those usage requests: Claude Code's to Anthropic, one to ChatGPT per Codex account, one to Kimi per Kimi home (the only addresses the binary itself calls: CODEX_USAGE_URL in usage.rs, DEFAULT_USAGE_URL and GLOBAL_USAGE_URL in kimi.rs), and Antigravity CLI's own /usage to Google, with the model list it fetches first to say it's signed in.
  • Nothing runs in the background. No daemon; the app's engine lives only while the app does (serve.rs).
  • Every change to a session can be undone. move deletes the original only once every copied file is checked, never puts an older copy over a newer one, and is undone by moving the session back; fork keeps the original; relocate prints the command that undoes it; and all three have a --dry-run that runs every check and writes nothing.
