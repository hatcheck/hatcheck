Every command

What hatcheck --help prints, then each command's own --help, as 0.5.0 prints them. The docs have each command as it is, with examples and its --json.

hatcheck: Claude Code, Codex, Antigravity CLI, Kimi Code CLI and ZCode accounts
on one computer, each kept apart. Lists recent sessions with the command that
resumes each one and what's left of each plan, and carries sessions between
accounts and agents.

Usage:
    hatcheck [sessions] [HOURS] ...    recent sessions in every profile and home, with
                                       resume commands and plan usage (the default)
    hat check ...                      the same as hat (or hatcheck): the name in two words
    hatcheck usage ...                 plan usage left for every profile and home
    hatcheck where SESSION             where a session is stored, by its ID or the start of it
    hatcheck move [SESSION] [PROFILE]  move a session to another profile or home, or convert
                                       it for another of the agents; with a profile alone,
                                       the newest session started here goes to it, and
                                       with nothing, to the best account now, after asking
    hatcheck fork [SESSION] [PROFILE]  fork a session into another profile or home: a new
                                       session with its own ID, and the original stays
    hatcheck relocate OLD NEW          bring the sessions of a project folder that was moved
                                       or renamed along to its new place
    hatcheck open [SESSION] ...        resume a session in a new terminal, in its folder
    hatcheck resume [SESSION]          carry on the newest session started here, in this
                                       terminal, after asking; hat r for short
    hatcheck show SESSION              a session's conversation, read-only
    hatcheck best [--for SESSION]      the best account now, in full, and the move command
                                       that carries the newest session started here to it;
                                       --wait sleeps until one has room
    hatcheck bind PROFILE ...          tie a folder to a profile, for cl, cx, ck and the list
    hatcheck unbind [FOLDER]           untie it again
    hatcheck desktop ...               Claude Desktop instances on macOS: list, open, make one
    hatcheck provider ...              the Z.ai and Kimi keys and models behind claude-z,
                                       claude-k, cl -z and cl -k
    hatcheck doctor                    every copy of hatcheck and the agents on your PATH,
                                       which runs, and how to remove the rest

hatcheck, usage, where, show, desktop, move, fork, relocate and doctor take --json,
for scripts, status bars and the desktop app.

`hatcheck SUBCOMMAND --help` lists a subcommand's options, and hatcheck --version
says which version this is. hat is the short name: hat usage is hatcheck usage,
and so on. cl, cx and ck run Claude Code, Codex and Kimi Code CLI with a profile.

A subcommand can be cut to its first letters: hat m is hat move, hat f is hat
fork. Where two share a letter, it goes to the one used more: b is best, s is
show, u is usage, d is desktop and r is resume, so bind, unbind and doctor take
two letters, bi, un and do, and relocate three, rel.
hatcheck sessionsrecent sessions in every profile and home, with resume commands and plan usage; the default 
usage: hatcheck sessions [-h] [-n N] [--all] [--all-folders] [--full]
                         [--cached] [--no-usage] [--json] [-e]
                         [hours]

List recent Claude Code CLI sessions across all ~/.claude* profiles, Codex CLI
sessions across all ~/.codex* homes, Antigravity CLI sessions from
~/.gemini/antigravity-cli, Kimi Code CLI sessions across all ~/.kimi-code*
homes and ZCode sessions from ~/.zcode, with the command that resumes each
one.

positional arguments:
  hours               how far back to look (default 24); accepts 36, 1.5, 12h
                      or 3d

options:
  -h, --help          show this help message and exit
  -n, --per-folder N  show only the newest N sessions per folder (default:
                      all)
  --all               also list sessions last used from Claude Desktop or the
                      SDK, Codex sessions from the Codex app, its IDE
                      extension or codex exec, and the Antigravity app's
                      conversations
  --all-folders       list every folder, even when run from a folder that has
                      sessions
  --full              print CLAUDE_CONFIG_DIR=... claude instead of the cl
                      shortcut, CODEX_HOME=... codex instead of cx, and
                      KIMI_CODE_HOME=... kimi instead of ck
  --cached            take plan usage from the snapshots Claude Code and Codex
                      last saved, and hatcheck's last readings of agy's /usage
                      and Kimi's usage, instead of the APIs
  --no-usage          leave plan usage out
  --json              print the sessions, and the accounts behind them, as
                      JSON for scripts and apps
  -e, --email         with --json, include each account's email address
hatcheck usageplan usage left for every profile and home 
usage: hatcheck usage [-h] [--cached] [-e] [--json]

Show how much of each plan limit is left, for every Claude Code profile
(~/.claude*), Codex home (~/.codex*), Antigravity CLI folder
(~/.gemini/antigravity-cli) and Kimi home (~/.kimi-code*); ZCode's folder is
listed with why zcode gives none.

options:
  -h, --help   show this help message and exit
  --cached     don't call the APIs; show the snapshots Claude Code and Codex
               last saved, and hatcheck's last readings of agy's /usage and
               Kimi's usage
  -e, --email  show each account's email address (hidden by default)
  --json       print the accounts and their limits as JSON, for scripts and
               status bars
hatcheck bestthe best account now, and the move command that carries a session to it 
usage: hatcheck best [-h] [--for SESSION] [--cached] [--wait [PROFILE]]

The best account now, shown as hatcheck usage shows it, and the hatcheck move
command that carries a session to it: the newest started from this folder, or
--for's. Advice only: it never starts, moves or switches anything.

options:
  -h, --help        show this help message and exit
  --for SESSION     the session to carry: its ID, or the start of it (default:
                    the newest session started from this folder)
  --cached          don't call the APIs; use the snapshots Claude Code and
                    Codex last saved, and hatcheck's last readings of agy's
                    /usage and Kimi's usage
  --wait [PROFILE]  wait until an account has room, then answer: any account
                    of the session's agent (Claude Code's, without a session),
                    or PROFILE's (NAME, default, codex, codex:NAME, agy, kimi,
                    kimi:NAME)

hatcheck movemove a session to another profile or home, or convert it for another agent 
usage: hatcheck move [-h] [--from PROFILE] [--keep] [--dry-run] [--json]
                     [session] [profile]

Move a Claude Code, Codex, Antigravity CLI, Kimi Code CLI or ZCode session to
another profile, to carry on with it there, or convert it for another agent.
With a profile alone, the newest session started from this folder goes to it;
with nothing, or a session alone, to the best account of its agent now, as
hatcheck best picks it; either after asking.

positional arguments:
  session         the session ID, or the start of it (default: the newest
                  session started from this folder; one word that names a
                  profile is PROFILE)
  profile         where it goes: NAME for ~/.claude-NAME, default or claude
                  for ~/.claude, codex for ~/.codex, codex:NAME for ~/.codex-
                  NAME, agy for ~/.gemini/antigravity-cli, kimi for ~/.kimi-
                  code, kimi:NAME for ~/.kimi-code-NAME, zcode for ~/.zcode,
                  or a path (default: the best account of the session's agent
                  now, as hatcheck best picks it)

options:
  -h, --help      show this help message and exit
  --from PROFILE  the profile or home to take it from, when more than one has
                  it
  --keep          keep the original, which copies the session rather than
                  moving it (a converted session's original is always kept)
  --dry-run       show what would be moved, copied, converted and deleted, and
                  change nothing
  --json          say what was or would be done as JSON, and never ask to
                  resume it
hatcheck forkfork a session into another profile or home: a new session with its own ID 
usage: hatcheck fork [-h] [--from PROFILE] [--dry-run] [--json]
                     [session] [profile]

Fork a Claude Code, Codex, Antigravity CLI, Kimi Code CLI or ZCode session
into another profile: bring it in as a new session with its own ID, beside any
copy already there, and keep the original. For another agent, it's converted.
With a profile alone, the newest session started from this folder goes into
it; with nothing, or a session alone, into the best account of its agent now,
as hatcheck best picks it; either after asking.

positional arguments:
  session         the session ID, or the start of it (default: the newest
                  session started from this folder; one word that names a
                  profile is PROFILE)
  profile         where it goes: NAME for ~/.claude-NAME, default or claude
                  for ~/.claude, codex for ~/.codex, codex:NAME for ~/.codex-
                  NAME, agy for ~/.gemini/antigravity-cli, kimi for ~/.kimi-
                  code, kimi:NAME for ~/.kimi-code-NAME, zcode for ~/.zcode,
                  or a path (default: the best account of the session's agent
                  now, as hatcheck best picks it)

options:
  -h, --help      show this help message and exit
  --from PROFILE  the profile or home to take it from, when more than one has
                  it
  --dry-run       show what would be copied or converted, and change nothing
  --json          say what was or would be done as JSON, and never ask to
                  resume it
hatcheck relocatea moved project folder's sessions, brought along 
usage: hatcheck relocate [-h] [--dry-run] [--json] old new

Bring the sessions of a project folder that was moved or renamed along to its
new place, in every Claude Code profile and Codex home: OLD is where they ran,
NEW where the folder is now.

positional arguments:
  old         the folder the sessions ran in, as it was
  new         the folder as it is now; it has to exist

options:
  -h, --help  show this help message and exit
  --dry-run   say what would move and change nothing
  --json      say what was or would be done as JSON
hatcheck openresume a session in a new terminal, in its folder 
usage: hatcheck open [-h] [--from PROFILE] [--here | --print]
                     [--terminal NAME] [--full] [--all] [--login PROFILE]
                     [session]

Resume a Claude Code, Codex, Antigravity CLI, Kimi Code CLI or ZCode session
in a new terminal window, already in its folder.

positional arguments:
  session          the session ID, or the start of it (default: the newest
                   session started from this folder)

options:
  -h, --help       show this help message and exit
  --from PROFILE   the profile or home to take it from, when more than one has
                   a copy
  --here           resume it in this terminal instead
  --print          print the cd and resume commands instead
  --terminal NAME  the terminal to open (default: HATCHECK_TERMINAL, or this
                   system's usual one)
  --full           print CLAUDE_CONFIG_DIR=... claude rather than cl,
                   CODEX_HOME=... codex rather than cx, and KIMI_CODE_HOME=...
                   kimi rather than ck
  --all            without SESSION, also consider sessions from Claude
                   Desktop, the SDK, the Codex app or codex exec
  --login PROFILE  sign in to a profile (NAME, default, codex, codex:NAME,
                   agy, kimi, kimi:NAME or zcode) in a new terminal, instead
                   of resuming a session

hatcheck bindtie a folder to a profile, for cl, cx, ck and the list 
usage: hatcheck bind [-h] [--codex HOME] [--agy FOLDER] [--kimi HOME]
                     [--zcode FOLDER] [--list] [--hook]
                     [profile] [folder]

Tie a folder to a profile, so cl, cx and ck pick it there and the session list
flags work done under another one.

positional arguments:
  profile         NAME for ~/.claude-NAME, default for ~/.claude, or a path
  folder          the folder to bind (default: this one)

options:
  -h, --help      show this help message and exit
  --codex HOME    the Codex home to bind: NAME for ~/.codex-NAME, default for
                  ~/.codex, or a path (default: the one named like PROFILE)
  --agy FOLDER    the Antigravity CLI folder to bind: default for
                  ~/.gemini/antigravity-cli, or a path (default: that one,
                  when PROFILE is default)
  --kimi HOME     the Kimi home to bind: NAME for ~/.kimi-code-NAME, default
                  for ~/.kimi-code, or a path (default: the one named like
                  PROFILE)
  --zcode FOLDER  the ZCode folder to bind: default for ~/.zcode, or a path
                  (default: that one, when PROFILE is default)
  --list          list every bound folder
  --hook          warn in Claude Code, Codex and agy when a session starts in
                  a bound folder under another profile
hatcheck unbinduntie it again 
usage: hatcheck unbind [-h] [--hook] [folder]

Remove a folder's binding, or the warning hook.

positional arguments:
  folder      the bound folder (default: this one)

options:
  -h, --help  show this help message and exit
  --hook      remove the warning hook from every profile
hatcheck desktopClaude Desktop instances on macOS 
usage: hatcheck desktop [-h] [--json] {new,open,remove} ...

Claude Desktop instances on macOS: one per account, each with its own data
folder and a launcher of its own colour.

positional arguments:
  {new,open,remove}
    new              make an instance's launcher, /Applications/Claude
                     DISPLAY.app
    open             start an instance, or bring it forward
    remove           delete an instance's launcher

options:
  -h, --help         show this help message and exit
  --json             list the instances as JSON
