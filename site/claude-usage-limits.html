Claude usage limits: what's left of each plan

A Claude plan's limits come in windows. There is a 5-hour session limit, which fills as you work and resets five hours after it started; a weekly limit; and on Team and Max plans a weekly limit for a single model, such as Fable, beside the one for all models. In Claude Code, /usage shows them for the account you're signed in to. With more than one account, hatcheck usage shows all of them in one list, each with what's left and how long until it resets, sorted by which to use first:

$ hatcheck usage
Plan usage by profile (% left, then time left until reset)
Sorted by Fable: those with some left first, the soonest reset on top, any past 90% used behind them; then those out of it, the soonest back on top.

Reading the bars

  • Each limit has two bars: what's left of it, then how much of its window is left before it resets. In a terminal the second goes from blue with most of the window to go, through gold and orange, to red as the reset nears.
  • When the first bar is shorter than the second, the limit is being used up faster than its window runs out.
  • A limit without a reset time, such as an unused 5-hour session, has no time bar. A ? means unknown: a limit that reset since its reading was saved is never shown as full or empty.
  • A per-model limit such as week (Fable) is named in violet, with its bar drawn in it, to tell it from week (all models).

Where the numbers come from

From Claude Code itself. claude -p /usage is run in each profile, with no tools or settings, which asks Anthropic with that profile's own login and saves the answer in the profile; hatcheck reads that snapshot and never a login. The runs take about a second each, in parallel. A reading under a minute old is shown as it is, since Claude Code's own /usage wouldn't ask again either. When nothing new comes back, because claude isn't installed, the profile isn't signed in, you're offline or Anthropic is rate-limiting the account, the last saved snapshot is shown with its age and the reason, as cached, never as fresh. hat u --cached asks nothing and shows what each agent last saved.

Which account to use now

The list is sorted by the per-model limit, Fable first: accounts with some left, the soonest reset on top, because what's left there goes to waste once it resets, so it's the one to use first. An account nearly out of it goes behind the fresher ones. Then come those out of it, the soonest back on top, then accounts without such a limit, such as Pro plans, and the Codex and Kimi homes. hat b puts it in one line, with the command that carries the newest session from this folder to the account with the most room; it is advice only, and nothing is started, moved or switched on its own. Claude Code with two accounts shows it in use.

The other agents' plans

Codex homes show their ChatGPT plan's 5-hour and weekly windows, and limits for single models, from the endpoint Codex's own /status asks, with the token Codex saved sent as it is and never refreshed; expired, the newest limits recorded in that home's sessions are shown with their age. Kimi homes show their Kimi Code plan's 5-hour, 7-day and monthly windows the same way. Antigravity CLI's folder shows what its own /usage reports, asked only once agy models has said it's signed in, so that nothing starts a sign-in. ZCode, DeepSeek Harness, MiniMax Code, Qwen Code, GitHub Copilot CLI and OpenCode have no plan-usage command or endpoint hatcheck asks, and each is listed with no data and the reason; which agents, and how far has the table.

In the menu bar

The app shows the same bars for every account in the menu bar, and sends a notification when a limit runs low, when a low one resets, and when a limit is about to reset with much of it unused, since that's the account to use now. Live usage is opt-in there. It isn't released yet; the app says where it stands.
